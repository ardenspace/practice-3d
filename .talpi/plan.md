# Plan: practice-3d — 키보드 접근과 상시 작품 목록

## Phase 1: 작품 목록을 열고 볼 수 있다

아이콘을 눌러 작품 목록을 열고, 이미지와 제목과 한 줄 소개를 보고, 작품을
골라 들어갔다가 돌아올 수 있다. 주소가 `/works` 로 바뀌고 뒤로가기로 닫힌다.

Contracts: B5

<!-- 조기 착수 메모: B5 는 슬라이드와 전체 화면 두 모습을 모두 규정하므로
     이 페이즈가 둘 다 만든다. 전체 화면 모습에 실제로 도달하는 경로(씬을
     못 띄우는 방문자)는 Phase 2 가 잇는다. -->

- [ ] B5 를 실패하는 테스트로 핀다. 씬을 마운트하지 않고 두 모습을 각각
      렌더하는 seam, 등록부 파생(항목 수·제목·소개·이미지 경로·링크 주소),
      빈 등록부 문구, 이미지 실패 시 텍스트 유지, 슬라이드에는 제목·태그라인이
      없고 전체 화면에는 있다는 규칙.
- [ ] 작품 목록 컴포넌트를 만든다. 등록부에서 파생된 항목(오브제 이미지,
      제목, 한 줄 소개, `/works/<slug>` 를 가리키는 진짜 링크), 이미지 실패
      시 제목과 소개 유지, 빈 등록부 문구, 슬라이드와 전체 화면 두 모습,
      제목·태그라인은 씬 홈이 그리지 않을 때만 목록이 그리는 규칙.
- [ ] `/works` 라우트를 낸다. 목록 화면이 홈 화면과 구별되는 자기 표식을
      갖고, 방울 씬 홈 오른쪽 위에 이름 붙은 아이콘이 생기고, 아이콘을 누르면
      주소가 `/works` 로 바뀌며 슬라이드가 열리고 뒤로가기로 닫힌다.
- [ ] 슬라이드를 창처럼 만든다. 열려 있는 동안 뒤의 씬은 마우스에 반응하지
      않고, 바깥을 클릭하면 닫히면서 뒤가 다시 살아나고, 항목이 많으면 목록
      안에서 스크롤된다. 목록을 닫고 열어도 씬이 처음부터 다시 뜨지 않는다.

## Phase 2: 씬을 못 띄우는 방문자가 목록에 닿는다

WebGL 이 없는 브라우저로 홈에 들어가면 전체 화면 작품 목록과 안내 문구가
보인다. 그 화면이 그 방문자의 홈이라 닫히지 않고, 뒤로가기가 고리에 갇히지
않는다.

Contracts: B4

- [ ] B4 를 실패하는 테스트로 핀다. 씬 불가 시 `/works` 로 갈아치기(히스토리를
      남기지 않는다), 안내 문구가 붙는 경우와 안 붙는 경우, 뒤로가기가 `/` 와
      `/works` 사이를 오가지 않음, 작품 목록을 그리는 곳이 온 사이트에 하나임.
- [ ] `HomeFallback` 에서 작품 링크 목록을 걷어내고, `/` 의 씬 불가 판정이
      `/works` 로 갈아치도록 바꾼다. 안내 문구를 토큰 모듈에 두고 뜻하지 않은
      이동일 때만 붙인다.
- [ ] 실행 중 전이를 잇는다. 컨텍스트 상실이나 씬 마운트 실패 시 이동 없이
      목록이 화면 전체로 바뀌고 문구가 붙으며, 초점이 사라진 요소에 남지
      않는다. `webglcontextrestored` 가 와도 화면을 되돌리지 않는다.

## Phase 3: 키보드만으로 모든 작품에 도달한다

마우스와 터치를 한 번도 쓰지 않고 홈에서 방울을 훑고, 작품에 들어가고,
나오고, 목록을 열고 닫을 수 있다. 스펙의 스모크 경로가 끝까지 통과한다.

Contracts: B1, B2, B3

<!-- 조기 착수 메모: B3 의 히스토리 표 가운데 목록 열기 행은 Phase 1 이,
     씬 불가 이동 행은 Phase 2 가 이미 구현했다. 이 페이즈의 핀은 그 행들에
     대해서는 새 구현이 아니라 적합성 확인이 된다. B1 의 (b)(c) 도 마찬가지다. -->

- [ ] B1·B2·B3 를 실패하는 테스트로 핀다. 등록부 항목을 하나 더 넣으면 순회·
      목록·라우트·Esc 가 따라오는지, 키의 뜻과 활성 항목 목록 개념, 탭이
      페이지를 벗어남, 히스토리 표의 다섯 행.
- [ ] 키 해석 계층을 순수 모듈로 만든다. 방울·3D·씬을 모른 채 항목 개수와
      현재 위치만으로 이전·다음·순환을 내놓는다. 왼쪽·위가 이전, 오른쪽·아래가
      다음이다. 씬 폴더 밖에 둔다.
- [ ] 씬의 키보드 초점과 탭 순서를 만든다. 씬이 DOM 초점 정거장 하나를
      차지하고, 홈에서 방향키를 누르면 초점이 씬으로 들어오며(페이지 스크롤은
      막고 항목이 보이도록 따라간다), 초점이 간 방울에 초점 표시가 보이고,
      엔터로 작품이 열린다. 탭은 씬 → 아이콘 → 페이지 밖, Shift+탭은 그 반대.
- [ ] 목록 안의 키보드 조작을 만든다. 방향키로 항목 사이를 순환하며 화면 밖
      항목까지 따라 스크롤되고, 슬라이드에서는 탭이 목록 안에 머물고 전체
      화면에서는 페이지를 벗어나며, Esc 로 슬라이드를 닫으면 초점이 아이콘으로
      돌아간다. 전체 화면에서는 Esc 와 바깥 클릭이 아무 일도 하지 않는다.
- [ ] 작품 페이지에서 나오는 길을 등록부 파생 라우팅에 얹는다. Esc 가 들어온
      자리(방울 또는 목록 항목)로 돌아가고, 들어온 자리가 없으면 주소에 적힌
      작품에서 목적지를 구하며, 그 기억은 페이지 수명을 넘기지 않는다.
      히스토리는 늘어나지 않는다.

## Phase 4: 화면을 보지 않는 사람에게도 전달된다

VoiceOver 를 켜고도 방울 사이를 옮겨 다니며 지금 몇 번째 작품인지 듣고,
목록이 열린 것을 알고, 씬을 못 띄웠을 때 왜 다른 화면에 왔는지 들을 수 있다.

Contracts: B6

- [ ] B6 를 실패하는 테스트로 핀다. 자동으로 확인할 수 있는 것들 — 아이콘의
      이름, 오브제 이미지의 설명이 제목과 소개에서 파생됨, 씬 방울들이 목록
      구조로 드러나고 위치 정보가 붙음, 안내 문구와 빈 등록부 문구가 낭독
      표면에 존재함, 슬라이드가 열린 동안 뒤 씬이 숨겨짐.
- [ ] 씬을 보조기술에 드러내는 층을 만든다. 작품 방울들이 하나의 목록으로
      드러나고, 초점이 있는 항목의 이름과 전체 안에서의 위치가 읽히며, 씬에
      초점이 닿으면 방향키·엔터·Esc 로 조작한다는 것이 읽힌다.
- [ ] 목록과 아이콘과 안내 문구의 보조기술 표면을 잇는다. 아이콘 이름, 이미지
      설명, 목록이 열렸다는 알림, 슬라이드 뒤 씬 숨김, 안내 문구와 빈 등록부
      문구의 낭독.
- [ ] 키보드 안내를 붙인다. 소리로는 씬에 닿을 때 항상, 화면에는 방문자가
      키보드를 쓰기 시작한 순간에만 나타나고 마우스만 쓰는 사람에게는 끝까지
      보이지 않는다. 슬라이드 움직임과 초점 표시에 `prefers-reduced-motion`
      규율을 적용한다.
- [ ] `.talpi/manual-check.md` 를 쓴다. 키보드 스모크 경로와 Shift+탭, 등록부
      임시 복제로 순환 확인하고 되돌리기, 슬라이드가 뒤를 잠그는지, 새로고침
      뒤 안내 문구가 사라지는지, 작품 페이지 새로고침 뒤 Esc 의 목적지,
      개발자 도구로 컨텍스트를 잃게 만들었을 때의 초점, 색 대비, 그리고
      VoiceOver 를 처음 쓰는 사람을 위한 켜고 끄는 법과 들어야 할 것.
