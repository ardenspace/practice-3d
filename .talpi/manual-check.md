# 수동 검수 체크리스트 (사람 눈·귀·손으로 보는 마지막 패스)

자동 테스트가 이미 확인한 것은 여기 없다. 여기 있는 것은 **화면이 실제로 떠야
알 수 있는 것**, **탭 키를 실제로 눌러야 알 수 있는 것**, **귀로 들어야 알 수
있는 것**뿐이다.

## 준비

- `bun run build && bun run preview` → `http://localhost:4173`. 빌드 산출물
  기준이 진실이므로 기본은 preview 다.
- `bun run dev` → `http://localhost:5173`. **코드를 건드리는 절**(§2 등록부 임시
  복제, §13 에러 바운더리)은 dev 를 쓴다. 고치면 곧바로 반영된다.
- 위에서 아래로 한 번 훑으면 끝나도록 배열해 두었다. 앞 절이 뒤 절의 준비가
  되는 자리가 있으니(§2 의 복제본으로 §3·§5·§7 를 보면 더 잘 보인다) 순서대로
  걷는 편이 낫다.
- **되돌려야 하는 절이 셋 있다**: §2(등록부 복제), §11(브라우저 설정),
  §13(임시 throw). 마지막 절 "마치기 전에 — 되돌릴 것"이 셋을 다시 챙긴다.

## 1. 키보드 스모크 경로 (마우스·터치를 한 번도 쓰지 않는다)

스펙이 정한 완주 조건이다. 주소창에 `localhost:4173` 을 치는 것 말고는 마우스에
손대지 않는다. 한 칸이라도 어긋나면 거기서 멈추고 무엇이 어긋났는지 적는다.

- [ ] 홈(`/`)에 들어간다. 아무것도 누르지 않은 상태에서 **초점이 씬으로 끌려가
      있지 않다.**
- [ ] **방향키 한 번** → 초점이 씬으로 들어가 첫 작품 방울이 잡힌다. 그 방울이
      멈추면서 안의 오브제가 드러나고 초점 고리가 보인다. 페이지가 방향키에
      밀려 스크롤되지 않는다.
- [ ] **방향키를 계속** → 등록부 순서대로 다음 작품 방울로 옮겨 가고, 마지막에서
      한 번 더 누르면 첫 작품으로 돌아온다. (등록부에 작품이 하나뿐이면 이 칸은
      제자리걸음이다 — 진짜 순환은 §2 에서 본다.)
- [ ] **엔터** → 방울이 터지고 `/works/vending-machine` 에 도착한다. 페이지가
      **한 번만** 열린다.
- [ ] **Esc** → 홈으로 돌아오고 초점 고리가 **방금 그 방울에** 있다 (첫 방울로
      튀지 않는다).
- [ ] **탭** → 오른쪽 위 아이콘으로 초점이 간다. 아이콘에 눈에 보이는 초점
      표시가 있다.
- [ ] **엔터** → 목록이 오른쪽에서 슬라이드로 열리고 주소가 `/works` 가 된다.
- [ ] 목록에 작품들이 **방울 안에서 보던 그 오브제 이미지, 제목, 한 줄 소개**와
      함께 들어 있다.
- [ ] 방향키로 항목을 골라 **엔터** → 그 작품 페이지. **Esc** → 목록이 다시
      열린 채 **그 항목에** 초점이 있다.
- [ ] **Esc 한 번 더** → 목록이 닫히고 초점이 아이콘으로 돌아온다 (눈에 보이게).
- [ ] **탭** → 초점이 페이지 밖(브라우저 주소창)으로 나간다.
- [ ] 여기까지 오는 동안 마우스를 한 번도 쓰지 않았다.

역방향(Shift+탭)으로 갇히지 않는지는 §3 과 §5 에서 본다.

## 2. 등록부를 잠시 둘로 늘려 보기 (되돌리기까지가 한 절이다)

지금 등록부에는 작품이 `vending-machine` 하나뿐이다. 방향키 순환은 작품이 둘
이상이어야 밟아 볼 수 있으므로 잠깐 하나를 복제한다. **이 절은 코드와 파일을
건드린다. 끝의 "되돌리기"까지 하고 나가라.**

`bun run dev`(5173)로 본다 — 등록부를 고치면 곧바로 반영된다.

### 만들기

`slug` 는 유일해야 하고 `object.src` 는 `/works/<slug>/` 로 시작해야 한다(테스트가
잡는다). 에셋 폴더를 새로 만들 필요는 없다 — 심볼릭 링크 한 줄이면 된다.

```sh
ln -s vending-machine public/works/vending-machine-2
```

그리고 `src/works/registry.ts` 의 `works` 배열 끝에 항목 하나를 더한다.

```ts
  {
    slug: 'vending-machine-2',
    title: `${VENDING_MACHINE_TITLE} 2`,
    blurb: VENDING_MACHINE_BLURB,
    object: { type: 'image', src: '/works/vending-machine-2/object.webp' },
    Page: VendingMachinePage,
  },
```

이 조합은 실제로 확인해 두었다: `bun run test` 전부 통과, `bun run build` 통과
(링크는 `dist/` 에 실제 파일로 풀려 복사된다), dev·preview 모두
`/works/vending-machine-2/object.webp` 를 200 으로 준다.

### 보기

- [ ] 홈에 방울이 **둘** 떠 있고, 방향키로 옮기면 등록부 순서대로 첫 번째 →
      두 번째로 가고, 두 번째에서 한 번 더 누르면 **첫 번째로 돌아온다.** 반대
      방향키(왼쪽·위)로는 정확히 역순으로 돈다.
- [ ] 목록을 열면 카드가 **둘**이다. 아이콘도 라우트도 손대지 않았는데 그냥
      나타난다. 새 카드의 이미지가 실제로 보인다.
- [ ] `/works/vending-machine-2` 로 직접 들어가도 페이지가 뜨고, Esc 로 나오면
      그 작품의 방울/항목에 초점이 간다.
- [ ] **따라 스크롤** (Requirement 18): 브라우저 창을 세로로 아주 좁혀 슬라이드
      목록이 넘치게 만든 뒤 화면 밖 항목으로 방향키를 옮긴다. 슬라이드 자기
      영역이 스크롤되어 그 항목이 보이고, **뒤 페이지는 움직이지 않는다.**
      (항목이 둘로 부족하면 위 블록을 `-3`, `-4` 로 몇 개 더 붙인다 — 링크도
      slug 마다 하나씩.)

### 되돌리기 (빼먹지 말 것)

```sh
git checkout src/works/registry.ts
rm public/works/vending-machine-2   # 심볼릭 링크라 rm 한 줄이면 된다
git status                          # 아무것도 남지 않아야 한다
```

- [ ] `git status` 가 깨끗하다. `public/works/` 안에 `vending-machine` 폴더
      하나만 남아 있다. (실수로 `rm -rf public/works/vending-machine/` 을 치지
      않도록 조심 — 지워야 하는 것은 링크뿐이다.)
- [ ] `bun run test` 가 통과한다.

## 3. 씬의 키보드 초점 — 세부

씬이 뜨는 상태에서 본다. jsdom 은 씬을 띄울 수 없고 탭 키도 구현하지 않아 아래는
전부 사람이 봐야 한다. 순회 규칙 자체(순서·순환·빈 등록부)는 자동 테스트가 이미
덮고 있으므로 여기서는 **화면에서 실제로 일어나는가**를 본다.

- [ ] 초점이 간 방울은 호버와 같은 상태가 된다 — 멈추고, 살짝 커지고, 안의
      오브제가 드러난다. 여기에 더해 **초점 고리**가 보인다.
- [ ] 초점이 어느 방울에 있는 상태에서 **다른** 방울에 마우스를 올린다. 둘 다
      멈추고 오브제가 드러나되 고리는 초점 쪽에만 있다. 엔터는 초점 쪽을,
      클릭은 커서 쪽을 연다.
- [ ] **탭 순서**: 주소창에서 탭 → 씬(고리가 첫 방울에 뜬다) → 탭 → 아이콘
      → 탭 → 페이지 밖. 씬 안의 방울이 여럿이어도 씬은 탭 한 번으로 지나간다.
- [ ] **Shift+탭**: 정확히 역순. 아이콘에서 누르면 씬으로, 씬에서 누르면
      페이지 밖으로. 정방향·역방향 어느 쪽으로도 페이지에 갇히지 않는다.
- [ ] 씬에 초점을 둔 채 엔터 → 방울이 터지고 작품 페이지가 **한 번만** 열린다.
      아이콘에 초점을 둔 채 엔터 → 목록이 열린다.
- [ ] **마우스만 쓰는 사람에게 고리가 보이지 않는다.** 씬 빈 곳을 마우스로
      클릭했을 때 방울 하나가 저 혼자 붙잡히지 않는다. (`:focus-visible`
      판정에 기대는 자리라 브라우저별로 갈릴 수 있다. Safari 15.4 미만은
      판정이 없어 "보이는 쪽"으로 기울게 해 두었다.)
- [ ] OS 설정에서 "동작 줄이기"를 켜고 방향키로 옮겨 다니면 고리가 미끄러지지
      않고 즉시 켜지고 꺼진다.
- [ ] 마우스와 터치 조작에 회귀가 없다 — 호버 공개, 클릭 팝, 길게 누르기.

## 4. 작품 페이지에서 나오는 길

- [ ] 홈에서 방향키로 방울 하나에 서고 엔터로 들어간 뒤 **Esc** → 씬이 뜬
      홈으로 돌아오고 **아까 그 방울에** 초점 고리가 있다(첫 방울로 튀지
      않는다).
- [ ] 작품 페이지에서 **방향키와 스페이스로 페이지가 정상 스크롤된다.**
      가로채기가 없어야 한다(Requirement 6).
- [ ] 목록 아이콘 → 항목 클릭 → 작품 → **Esc** → 슬라이드 목록이 다시 열린
      채 그 항목에 초점이 있다. 이어서 브라우저 뒤로가기를 눌러도 사이트
      밖으로 나가지 않는다(히스토리가 늘지 않았다).
- [ ] 주소창에 `/works/vending-machine` 을 직접 치고 **Esc** → 홈으로
      갈아치고 그 작품의 방울에 초점이 간다. 뒤로가기가 작품 페이지로
      돌아가지 않는다.
- [ ] **새로고침한 뒤 Esc**: 목록에서 들어갔든 방울에서 들어갔든, 작품 페이지에서
      새로고침을 한 번 하고 Esc 를 누른다. 들어온 자리의 기억은 페이지 수명을
      넘기지 않으므로, 목록에서 들어왔더라도 **목록이 다시 열리지 않고**
      기본 목적지 — 씬이 뜬 홈 — 로 간다. 초점은 그래도 그 작품의 방울에
      놓인다. 뒤로가기가 방금 그 작품 페이지로 되돌아가지 않는다.
- [ ] 위 경우들에서 초점이 **한 번만, 제대로** 놓인다. dev 서버는
      StrictMode 라 effect 가 두 번 돈다.
- [ ] 마우스로 "← 방울들에게로" 링크를 눌러 나온 경우에는 초점을 빼앗지
      않는다.

## 5. 작품 목록 — 슬라이드

씬이 뜨는 상태(WebGL 정상)에서 본다. 이 항목들은 jsdom 이 씬을 띄울 수 없어
자동으로 확인할 수 없다.

- [ ] 홈 오른쪽 위에 목록을 여는 아이콘(방울 세 개)이 보이고, 마우스를
      올리면 무엇을 여는 물건인지 알 수 있다("작품 목록 열기").
- [ ] 아이콘을 누르면 주소가 `/works` 로 바뀌고 슬라이드가 오른쪽에서 열린다.
      열려 있는 동안 아이콘과 씬 힌트는 사라진다.
- [ ] 슬라이드 안에 자판기 작품이 오브제 이미지·제목·한 줄 소개와 함께 있고,
      항목을 누르면 작품 페이지로 간다. 가운데 버튼으로 새 탭에 열리고 링크
      주소를 복사할 수 있다.
- [ ] **뒤 씬이 잠긴다**: 슬라이드가 열린 동안 뒤의 방울에 마우스를 올려도
      멈추거나 커지지 않고, 클릭해도 터지지 않는다. 방울은 계속 떠다닌다.
- [ ] **바깥 클릭으로 닫힌다**: 슬라이드 바깥(왼쪽 씬 영역)을 클릭하면 목록이
      닫히고, 뒤의 씬이 다시 마우스에 반응하며, 초점이 아이콘으로 돌아간다.
- [ ] **씬이 다시 뜨지 않는다**: 목록을 열고 닫기를 서너 번 반복해도 방울이
      처음부터 다시 떠오르지 않고 하던 움직임을 이어간다. DevTools Console 에
      three.js 재초기화 로그나 에러가 없다.
- [ ] **히스토리**: 아이콘으로 연 뒤 브라우저 뒤로가기 한 번에 목록이 닫히고
      `/` 로 돌아간다. 바깥 클릭으로 닫은 뒤 뒤로가기를 누르면 사이트 밖으로
      나가지 않는다.
- [ ] **딥링크**: 주소창에 `/works` 를 직접 입력해도 같은 슬라이드가 뜬다.
      그 상태에서 바깥을 클릭해 닫으면 사이트 밖으로 튕겨 나가지 않고 홈에
      머문다.
- [ ] **목록 안 방향키**: 슬라이드를 열고 아래 방향키를 반복해 누르면 초점이
      등록부 순서대로 카드를 돌고 끝에서 처음으로 순환한다. 뒤의 방울은 그동안
      만질 수 없다.
- [ ] **슬라이드의 탭 고리** (Requirement 17): 슬라이드가 열린 채
      마지막 카드에서 탭을 누르면 첫 카드로 돌아온다. 첫 카드에서 Shift+탭이면
      마지막 카드로 간다. 주소창으로 나가지 않는다. jsdom 이 탭을 실행하지
      못해 여기서만 확인된다.
- [ ] **Esc 로 닫기** (Requirement 20): 슬라이드가 열린 채 Esc 를
      누르면 목록이 닫히고 초점이 **눈에 보이게** 아이콘으로 간다. 아이콘으로
      연 경우와 주소창에 `/works` 를 직접 입력한 경우를 모두 해 본다(후자는
      `/` 로 갈아치는데, 그래도 초점은 아이콘에 닿아야 한다).
- [ ] **좁은 화면**: 브라우저 창을 좁히면 슬라이드가 화면을 가득 덮어 바깥이
      남지 않는다. 이때 목록을 닫을 방법이 뒤로가기뿐인 것이 받아들일 만한지
      본다. (페이즈 1 보고의 질문 항목)
- [ ] **움직임 축소**: OS 설정에서 "동작 줄이기"를 켠 뒤 목록을 열면 슬라이드가
      미끄러지지 않고 즉시 나타난다.

## 6. 색과 대비

값은 전부 위임 구역이다 — 안 보이면 고쳐도 된다. 어두운 우주 배경 위라 특히
"있는 줄 알았는데 안 보이는" 것이 생기기 쉬운 자리들이다.

- [ ] **초점 고리**가 우주 배경과 무지갯빛 림 위에서 실제로 눈에 띈다. 안 띄면
      `src/scene/constants.ts` 의 `FOCUS_RING_*` 값을 조정한다.
- [ ] **목록 카드**의 제목(시안)과 한 줄 소개가 카드 면 위에서 읽을 만하다.
      오브제 이미지가 없는 자리(이미지 로드 실패)도 빈 구멍처럼 보이지 않는다.
      전체 화면 목록과 슬라이드 양쪽에서 본다 — 뒤에 깔린 것이 다르다.
- [ ] **목록을 여는 아이콘**이 배경의 밝은 성운 위에 놓여도 사라지지 않는다.
      탭으로 초점이 갔을 때 브라우저 기본 초점 표시가 유리면 위에서 보인다.
- [ ] **키보드 안내 한 줄**("방향키로 방울 사이를 옮기고…")이 화면 아래에서
      실제로 읽히는 밝기다. 마우스 힌트보다 조용한 것이 의도지만 안 보이면
      의도가 아니다.
- [ ] **씬 폴백 안내 띠**(§11 에서 보게 된다)의 글자가 반투명 유리면 위에서
      읽힌다.

## 7. VoiceOver — 화면을 보지 않는 사람이 듣는 것 (B6)

이 절은 macOS VoiceOver 를 처음 켜 보는 사람을 위한 것이다. **Safari 로** 보는
것을 권한다 (macOS VoiceOver 와 가장 잘 맞는다). 아래 단축키는 macOS VoiceOver 의
표준 조작이지만 이 문서가 대신 눌러 본 것은 아니다 — 안 맞으면 VoiceOver 메뉴
(`VO`+M)나 VoiceOver 유틸리티에서 같은 기능을 찾을 수 있다.

### 켜고 끄기 (이것만 알면 언제든 빠져나올 수 있다)

- **켜기/끄기: `⌘F5`.** 같은 키가 토글이다. 시스템 설정 → 손쉬운 사용 →
  VoiceOver 에서도 켤 수 있다.
- 처음 켜면 환영 창이 뜬다. 튜토리얼은 5분쯤 걸리고 한 번은 해 볼 값어치가
  있지만, 건너뛰려면 그냥 닫으면 된다.
- **말이 너무 빠르거나 시끄러우면**: `Control` 키를 한 번 누르면 지금 읽던
  것이 즉시 멈춘다. 말하는 속도는 VoiceOver 유틸리티(`VO`+F8) → 말하기에서
  바꾼다.
- **`VO` 키 = `Control`+`Option`.** 이 절에서 `VO`+X 라고 쓰면 세 키를 함께
  누르라는 뜻이다.
- **캡션 패널을 켜 두면 검수가 훨씬 쉽다.** VoiceOver 가 지금 읽는 문장을 화면
  아래에 글자로도 보여 준다 — 들은 것을 눈으로 대조할 수 있다. VoiceOver
  유틸리티 → 시각 자료 → 캡션 패널.
- 이 절에서 쓰는 조작은 다섯뿐이다: `Tab`(다음 초점), `VO`+→ / `VO`+←(다음/이전
  항목 읽기), `VO`+A(여기서부터 쭉 읽기), `Control`(멈추기), `⌘F5`(끄기).

### 먼저 알아 둘 것 — 방향키가 안 먹을 수 있다

스크린 리더를 쓰는 방문자에게는 방향키가 **자기 읽기 키**다. 그래서 씬의 커서를
방향키로 못 움직일 수 있다. **이것은 버그가 아닐 수 있다** — 스펙의 Reversibility
Ledger 가 이 대가를 인정했고, 그 대신 그 방문자를 위해 씬이 탭 정거장 하나로
존재하며 조작법이 소리로 읽힌다.

씬에 초점을 둔 채 아래를 위에서부터 시도해 보고, **어느 것이 통했는지(또는 하나도
안 통했는지) 적어 둔다.**

- [ ] ① 그냥 방향키를 눌러 본다. 커서가 방울 사이를 옮기고 위치가 읽히면 그대로
      진행한다.
- [ ] ② 방향키가 VoiceOver 커서를 움직이면 **빠른 탐색(Quick Nav)** 이 켜져 있는
      것이다. `←` 와 `→` 를 **동시에** 눌러 끈 뒤 다시 해 본다.
- [ ] ③ 그래도 안 되면 씬 정거장에 VoiceOver 커서를 둔 채 **`VO`+Shift+↓** 로
      그룹 **안으로 들어간다**(interact). 나올 때는 `VO`+Shift+↑.
- [ ] ④ 한 번만 넘기고 싶으면 **`VO`+Tab** — 다음 키 조합 하나를 VoiceOver 가
      무시하고 페이지에 넘긴다.

### 들려야 하는 것 (B6 의 여섯 가지)

`bun run preview`(4173)로 홈에 들어가 VoiceOver 를 켠다. §2 의 복제본이 아직
있으면 "2개 중" 이 들리고, 되돌린 뒤라면 "1개 중 1번째" 가 들린다.

- [ ] **② 씬에 닿으면 조작법이 읽힌다.** 주소창에서 `Tab` 을 눌러 씬으로 들어가면
      이름과 역할과 설명이 이어서 들린다 — **"작품 방울 씬"**, 그룹, 그리고
      **"방향키로 방울 사이를 옮기고, 엔터로 그 작품을 엽니다. Esc를 누르면
      돌아옵니다."**
- [ ] **① 방울들이 하나의 목록으로 드러난다.** 씬 안을 `VO`+→ 로 훑으면 목록
      **"떠 있는 작품 방울"** 과 그 안의 항목 **"자판기"** 가 들린다. 항목은
      링크가 아니다 — "링크" 라고 읽히면 잘못된 것이다.
- [ ] **① 지금 몇 번째인지가 읽힌다.** 씬 커서를 옮기면(위 "방향키가 안 먹을 수
      있다" 참고) **"자판기, 1개 중 1번째"** 꼴로 들린다. 복제본이 있으면
      **"자판기 2, 2개 중 2번째"**.
- [ ] **③ 목록을 여는 아이콘에 이름이 있다.** `Tab` 으로 아이콘에 가면
      **"작품 목록 열기"** + "링크" 가 들린다. "링크", "이미지" 처럼 이름 없이
      읽히면 잘못된 것이다.
- [ ] **⑤ 목록이 열렸다는 사실이 전달된다.** 아이콘에서 엔터를 누른 직후
      **"작품 목록이 열렸습니다."** 가 저절로 들린다.
- [ ] **⑤ 열려 있는 동안 뒤의 씬은 읽히지 않는다.** 목록이 열린 채 `VO`+→ 로
      화면을 처음부터 끝까지 훑는다. "작품 방울 씬" 그룹도, "떠 있는 작품 방울"
      목록도 나오지 않아야 한다. 나오면 뒤와 앞이 섞여 들리는 것이다.
- [ ] **④ 목록의 오브제 이미지에 설명이 붙는다.** 목록 카드에 초점을 두면
      **"자판기 — 우주 한구석에서 방울을 파는 자판기."** 한 구절이 링크 이름으로
      들린다. 이미지 설명도 같은 문장이다. 제목과 소개가 그 뒤에 또 한 번
      이어 붙어 장황해지지 않는다.
- [ ] **⑥ 씬을 못 띄웠다는 안내가 소리로도 전달된다.** §11 의 방법으로 WebGL 을
      막고 홈에 들어가면, 화면을 만지기 전에 **"3D 씬을 띄우는 데 문제가 있어
      대신 작품 목록을 바로 볼 수 있는 페이지로 이동했습니다."** 가 저절로
      읽힌다. 그 상태에서 새로고침하면 화면에서도 소리에서도 이 문구가 없다.
- [ ] **같은 말이 두 번 들리지 않는다.** 화면 아래에 보이는 키보드 안내
      한 줄은 **읽히지 않는 것이 정상이다** — 같은 문장을 이미 씬 정거장의
      설명으로 들었기 때문이다. 두 번 들리면 그것이 버그다.
- [ ] 다 끝내고 **`⌘F5`** 로 VoiceOver 를 끈다.

## 8. 홈 — 방울 씬 (마우스, 데스크톱)

- [ ] 홈 접속 시 우주 배경(어두운 배경 + 성운) 위로 방울들이 떠다닌다.
      백지/검은 화면 없음, 콘솔 에러 없음 (DevTools Console 확인).
- [ ] 제목 + 태그라인("고요한 우주를 떠도는 방울들")이 보이고,
      잠시 뒤 하단에 힌트("방울을 톡, 터뜨려 보세요")가 페이드 인.
- [ ] **호버 → 정지 + 확대**: 아무 방울에나 마우스를 올리면 그 방울만
      멈추고 살짝 커진다. 커서가 pointer로 바뀐다.
- [ ] **작품 방울 오브제 공개**: 자판기 작품 방울에 호버하면 방울 안에
      자판기 오브제 이미지가 페이드/스케일 인으로 보인다.
      장식 방울은 호버해도 빈 채로 같은 반응(정지+확대)만 한다.
- [ ] **호버 해제 → 원복**: 커서를 떼면 오브제가 사라지고, 멈춘 자리에서
      순간이동 없이 다시 부드럽게 흘러간다.
- [ ] **작품 방울 클릭 → 터짐 → 이동**: 자판기 방울 클릭 시 무지갯빛
      파티클로 터지고, 터지는 연출 중에 `/works/vending-machine`으로
      전환된다 (연출이 뚝 끊기지 않고 자연스러운지).
- [ ] **장식 방울 클릭**: 터지기만 하고 이동 없음. 몇 초 뒤 화면 아래에서
      새 방울이 리스폰해 필드가 비지 않는다.
- [ ] 겹친 방울에 호버/클릭하면 앞의 방울 하나만 반응한다.
- [ ] 브라우저 창 리사이즈 후에도 방울 배치가 화면 안에서 자연스럽다.

## 12. 실행 중 씬 상실 (jsdom 으로 확인 불가)

WebGL 이 정상인 상태에서 시작한다. DevTools Console 에서 아래를 실행한다
(webgl2 가 null 이면 `'webgl'` 로 시도).

```
document.querySelector('canvas').getContext('webgl2').getExtension('WEBGL_lose_context').loseContext()
```

- [ ] **`/` 에서 실행** → 주소가 `/works` 로 바뀌며 전체 화면 목록이 되고
      안내 문구가 붙는다. 뒤로가기가 고리에 갇히지 않는다.
- [ ] **목록을 슬라이드로 열어 둔 `/works` 에서 실행** → **주소가 바뀌지
      않는다.** 슬라이드가 전체 화면으로 바뀌고 안내 문구가 붙는다. 사이트
      제목이 둘이 되거나 사라지지 않는다.
- [ ] 전이 순간에 **깜빡임이나 중간 화면이 없다.**
- [ ] **방울에 초점이 있던 상태에서 실행** → 초점이 `<body>` 로 떨어지지 않고
      **그 작품의 목록 항목**으로 옮겨 간다. 콘솔에 명령을 미리 붙여 넣어
      두고, 페이지로 돌아가 방향키로 방울에 선 다음, 콘솔로 옮겨 Enter 만
      친다(페이지를 클릭하면 초점을 잃는다). 실행 뒤 콘솔에서
      `document.activeElement` 를 보면 `data-work-slug` 를 단 링크여야 한다.
      이어서 탭을 누르면 목록 안 다음 항목으로 간다.
- [ ] 슬라이드의 작품 카드에 초점을 둔 채(탭으로 이동) 실행 → 초점이
      `<body>` 로 떨어지지 않고 목록 안에 남는다. DevTools Console 에서
      `document.activeElement` 로 확인한다.
- [ ] 컨텍스트가 뒤늦게 복구되어도(`restoreContext()`) 화면이 저절로 씬으로
      되돌아가지 않는다.
- [ ] 무너진 뒤 작품 페이지에 들어갔다가 홈 링크로 돌아오면 방울이 다시 뜰
      수 있다. 방문자가 직접 이동한 결과라 스펙 위반은 아니지만, 겪어 보고
      받아들일 만한지 본다. (페이즈 2 보고의 확인 항목)
