# Spec: practice-3d — 비눗방울 오브제 포트폴리오

## Product Picture

지금은 arden 혼자 보는 3D 연습장이고, 나중에 개인 포트폴리오로 공개한다.
오늘까지는 Blender 렌더가 로컬 폴더에만 쌓여 있었다.

핵심 경험: 우주 배경 위로 비눗방울들이 떠다닌다. 방울에 마우스를 올리면
(모바일: 길게 누르면) 방울이 멈추고 살짝 커지면서 안에 담긴 오브제 —
작품의 이미지 — 가 보인다. 방울 안에 작품이 갇혀 있는 모양새. 커서를
떼면 다시 평범한 방울로 흘러다닌다. 클릭하면 터지면서 그 작품 페이지로
이동한다. 이 호버→정지→오브제 공개→터짐의 순간이 기분 좋아야 한다.

작품 페이지는 갤러리 템플릿이 아니라 자유 놀이터다. 첫 작품인 자판기라면
페이지 안에 인터랙티브 자판기를 넣고 버튼을 누르면 음료가 나오는
무브먼트까지 — 페이지마다 하고 싶은 것을 다 한다.

용어: 오브제가 담긴 방울을 **작품 방울**, 나머지를 **장식 방울**이라
부른다. 이 문서 전체에서 이 두 용어만 쓴다.

스모크 시나리오: 홈 접속 → 방울들이 떠오름 → 자판기 작품 방울에 호버 →
방울이 멈추고 자판기 오브제가 보임 → 클릭 → 터짐 → `/works/vending-machine`
페이지 도착.

## Requirements

1. 홈에서 비눗방울들이 우주 배경 위로 계속 떠다닌다 (모션 세부는 위임).
2. 등록된 작품마다 작품 방울이 하나씩 생기고, 나머지는 장식 방울이다.
   v1 컬렉션은 첫 작품 **자판기(vending-machine)** 하나로 시작한다.
   기존 Bubbles in Space 렌더는 컬렉션에 넣지 않는다.
3. 데스크톱: 방울 호버 시 그 방울이 정지하고 확대된다. 작품 방울은
   오브제 이미지가 방울 안에 보이고, 장식 방울은 빈 채로 같은 반응을
   한다. 호버 해제 시 원래 상태로 돌아가 다시 흐른다.
4. 모바일: 길게 누르기가 호버와 동일하게 동작한다 (누르는 동안 정지+오브제,
   떼면 원복). 탭/길게 누르기를 가르는 시간 임계값은 단일 상수로 정의한다
   (기본값 250ms, 값 조정은 위임). 누른 시간이 임계값 미만이면 탭,
   이상이면 길게 누르기다.
5. 작품 방울 클릭(짧은 탭): 터짐 연출 후 해당 작품 페이지로 이동한다.
6. 장식 방울 클릭: 터지기만 하고 이동은 없다.
7. 작품 페이지는 `/works/<slug>`에 마운트되는 자유 React 컴포넌트다.
   단 하나의 의무: 홈으로 돌아가는 링크를 포함한다 (B1).
8. WebGL 컨텍스트를 만들 수 없거나 도중에 잃은 환경에서는 배경 이미지 +
   사이트 제목 + 작품 텍스트 링크 목록이 보인다 (백지 금지).
9. `bun install` / `bun run dev`로 설치·실행되고, 빌드 산출물은 정적
   파일만으로 동작한다. 런타임에 외부 네트워크 요청이 없다 (폰트 포함
   전부 셀프호스트).

## Out of Scope (v1)

- 배포 (Netlify + 개인 도메인은 다음 라운드)
- 사운드 (터짐 효과음 등)
- 접근성 대응 (prefers-reduced-motion 등)
- 방울 속 3D 미니 모델 오브제 (`object.type` 확장은 다음 라운드 이후)
- CMS/서버/DB — 어떤 형태로든 없음
- 자판기 페이지의 완성형 인터랙션 (버튼→음료 무브먼트 등) — 페이지는
  v1에서 최소 구성으로 시작하고, 작품 자체의 완성은 별도 작업

## Simplicity Zones

- 작품 데이터는 코드 안의 등록부 하나. 작품 추가 = 등록 항목 하나 +
  에셋 폴더 하나.
- 배경은 정적 이미지 한 장 (실시간 배경 셰이더 없음).
- 방울 개수/배치는 상수 하드코딩. 설정 UI 없음.
- 자동 테스트는 경계 계약(B1–B4)에만. 비주얼은 눈으로 검수.

## Boundary Contracts

### B1: 작품 등록 계약

작품 하나 = 등록부의 항목 하나:

- `slug`: `[a-z0-9-]+` 형식, 유일. 라우트 `/works/<slug>`가 된다.
  형식·유일성 검증은 테스트가 등록부를 로드해 수행한다.
- `title`: 문자열. 방울 라벨과 페이지에 쓰인다.
- `blurb`: 한 줄 소개 문자열.
- `object`: 판별 유니온. v1은 `{ type: 'image', src: string }` 하나만
  지원한다. `src`는 `/works/<해당 slug>/`로 시작하는 사이트 상대 경로만
  허용한다 (스킴/호스트 금지 — 외부 URL 불가. 경로 세그먼트에 `.`·`..`
  금지, `?`·`#` 금지). 오브제 표현의 교체(예:
  미래의 `type: 'model'`)는 등록부 항목 수준에서 일어난다.
- `Page`: 해당 라우트에 마운트될 React 컴포넌트. 렌더 결과에 홈(`/`)으로
  가는 링크가 존재해야 한다 (테스트 가능).

등록부 검증(slug 형식·유일성, `object.src` 형식)은 테스트에서 수행한다 —
위반은 테스트 실패이지 런타임 예외가 아니다 (런타임 백지 금지).

씬이 보장하는 것 (테스트 가능): 등록 항목이 N개면 작품 방울이 정확히
N개 생긴다. 항목을 추가하면 등록부와 에셋 폴더 밖의 코드를 수정하지
않아도 방울과 라우트가 늘어난다.

### B2: 에셋 파일 규약

- 작품 에셋은 전부 `public/works/<slug>/` 아래. 오브제 이미지는 정사각형,
  투명 배경 권장 (파일명은 `object.src`가 가리키는 것이 진실).
- 배경은 `public/backdrop.webp` 한 장.
- 등록된 모든 `object.src`는 빌드 산출물 기준으로 실제 존재해야 한다.
  매핑 규칙: 선행 `/`를 뗀 경로를 빌드 출력 루트(및 개발 시 `public/`)에
  대해 해석한 파일이 존재해야 한다. SPA 서버의 200 응답이 아니라 파일
  존재를 검사한다 (테스트 가능).
- 배경 이미지의 소스는 이 리포의 `renders/` Blender 산출물에서 가져온다
  (변환·선택은 위임).

### B3: 라우팅 표면

- `/` = 방울 씬 홈.
- `/works/<slug>` = 등록된 작품 페이지. 등록에 없는 slug나 알 수 없는
  경로는 홈으로 보낸다.
- SPA 딥링크(`/works/<slug>` 직접 접속)가 동작해야 한다. 검증 환경은
  SPA 폴백을 제공하는 `vite preview`로 한다. 프로덕션 호스팅의
  리다이렉트 설정은 배포 라운드 몫.

### B4: 씬 폴백 계약

- WebGL 컨텍스트 생성 실패 또는 실행 중 상실 시: 배경 이미지 위에
  사이트 제목 + 등록된 모든 작품의 텍스트 링크 목록을 렌더한다.
- 자동 테스트 범위는 "로드 시 차단" 케이스다: WebGL을 차단한 환경에서
  로드하면 모든 등록 작품의 링크가 보인다. 실행 중 상실은 같은 폴백
  의무를 지지만 검증은 수동 검수로 한다.

## Reversibility Ledger

### Decided (hard to change)

- 스택 표면: Vite + React + TypeScript + three.js(React Three Fiber) +
  react-router. 패키지 매니저는 bun. (애니메이션/헬퍼 라이브러리 선택은
  내부 구현으로 위임.)
- 정적 사이트 전제 — 서버 없이 영원히 정적 파일만으로 동작. 배포 타깃은
  Netlify + 개인 도메인 (다음 라운드).
- 공개 URL 형태는 `/works/<slug>` 전체가 영구다. 한번 공개된 slug와
  `/works/` 접두사는 변경하지 않는다.
- 등록부 스키마: `slug` / `title` / `blurb` / `object`(판별 유니온) /
  `Page` — B1의 형태 그대로가 데이터 모델이다.
- 콘텐츠는 코드와 함께 산다: 작품 추가·수정 = 코드 커밋. CMS 이전은
  계획에 없다.
- 오브제 표현의 교체는 등록부 항목 수준에서 일어난다 (v1: 이미지,
  이후: 3D 모델 등 — 씬 코드는 이 교체에 닫혀 있다).
- 초기(v1) 컬렉션은 자판기 하나다.
- 모바일 상호작용 매핑: 길게 누르기 = 호버, 짧은 탭 = 터뜨리기.
- 알 수 없는 경로는 홈으로 보낸다 (전용 404 페이지는 공개 시점에 재고
  — 패널의 SEO 지적을 인지하고 v1은 이대로 간다).

### Delegated (agent's discretion)

- 방울 모션 파라미터 (속도, 흔들림, 리스폰 규칙)
- 방울 재질/셰이더 색감, 무지갯빛 강도, `public/bubbles.glb` 사용 여부
  (사용하지 않기로 해도 파일 삭제는 사람에게 확인)
- 터짐 연출과 파티클 (개수, 수명, 물리)
- 오브제 표시 연출 (페이드/스케일 등)과 방울 확대 배율
- 장식 방울 개수와 배치
- 페이지 전환 연출
- 홈 타이포그래피와 카피
- 폴백 화면의 구체적 스타일
- 탭/길게 누르기 임계값의 구체 값 (상수 하나로 존재하는 것만 계약)
- 자판기 v1 페이지의 최소 구성 내용

## Conventions

- Baseline 3종 수락: (1) 반복 리터럴은 토큰/상수 모듈 한 곳에, 인라인
  중복 금지 (2) 두 번 나오는 로직은 공유 레이어로 추출하고 conventions.md에
  등록 (3) 사용자 노출 실패 문구는 한 가지 톤, 한 곳에서 정의.
- 디자인 무드: 홈(방울 씬)은 우주 무드 — 어두운 배경 + 보라 성운 +
  핑크/시안 광원 — 를 따른다. 색상 값의 관리 방식은 baseline 규칙 1을
  따르면 충분하다. 작품 페이지는 페이지마다 스타일 자유 (그것도 공부 목적).
- 실패 시: 조용하고 우아하게. 씬이 안 되면 배경 + 텍스트 링크 목록 폴백.
  작품 페이지 크래시는 에러 바운더리로 잡아 홈 링크가 있는 최소 화면을
  보인다. 백지 화면 금지.
- 런타임 외부 요청 금지: 폰트·스크립트·스타일 전부 셀프호스트. (자동
  테스트 범위는 B1–B4 유지 — 이 규칙은 리뷰/검수로 지킨다.)
- 자동 테스트 러너는 Vitest (Vite 생태계 기본).
